# Workspace Main

This is your central hub for managing all Copilot workspaces with GitHub as the single source of truth.

## Purpose

Ensure consistency across your workspaces on multiple computers by:
- **Comparing** local vs. remote versions
- **Auto-pulling** latest from GitHub
- **Migrating** workspaces to GitHub
- **Managing** central workspace registry

## Quick Start

### 1. Check Sync Status
```powershell
.\scripts\Compare-WorkspacesWithRemote.ps1 -Detailed
```
Shows which workspaces are behind, ahead, or up-to-date with GitHub.

### 2. Pull Latest from All Workspaces
```powershell
.\scripts\Pull-LatestFromAllWorkspaces.ps1
```
Synchronizes all workspaces to their latest GitHub versions.

### 3. Migrate Workspaces to GitHub
```powershell
.\scripts\Migrate-WorkspacesToGitHub.ps1
```
Migrates existing workspaces to GitHub repositories (run once).

## Key Concepts

### GitHub as Source of Truth
- Each workspace has its own GitHub repository
- Workspace Main pulls from remotes to synchronize
- Multi-computer sync via GitHub

### Workspace Registry
Central record in `config/workspaces-config.json`:
- Workspace names, paths, and descriptions
- GitHub repository URLs
- Last sync timestamps
- Sync enabled status

### Auto-Sync Philosophy
On any computer, before you start work:
1. Run comparison to see what's behind
2. Pull latest from GitHub
3. Work with current versions
4. Push changes back to GitHub
5. Next computer automatically gets updates

## Workflow Across Computers

**Computer A (Day 1):**
```powershell
# Check status
.\scripts\Compare-WorkspacesWithRemote.ps1

# Work on "SQL Queries" workspace
# Edit files, git add, git commit, git push

# End of day
.\scripts\Pull-LatestFromAllWorkspaces.ps1  # Sync any other changes
```

**Computer B (Day 2):**
```powershell
# Start work
.\scripts\Pull-LatestFromAllWorkspaces.ps1

# SQL Queries now has Computer A's changes
# Continue working
```

**Computer A (Day 2):**
```powershell
# Start work
.\scripts\Pull-LatestFromAllWorkspaces.ps1

# Get Computer B's changes
```

## Common Tasks

### View All Workspaces
```powershell
$reg = Get-Content config/workspaces-config.json | ConvertFrom-Json
$reg.workspaces | Format-Table name,path,github
```

### Check Specific Workspace Status
```powershell
# Manual check
cd "D:\COPilot Workspaces\SQL Queries"
git status
git log --oneline -5
```

### Update Workspace Registry
Edit `config/workspaces-config.json` to:
- Add new workspaces
- Remove old workspaces
- Update GitHub URLs
- Change descriptions

Then re-sync:
```powershell
.\scripts\Pull-LatestFromAllWorkspaces.ps1
```

### Push Changes from Computer A to GitHub
```powershell
cd "D:\COPilot Workspaces\SQL Queries"
git add .
git commit -m "Add performance index analysis"
git push origin main
```

Then on Computer B:
```powershell
.\scripts\Pull-LatestFromAllWorkspaces.ps1  # Automatically gets changes
```

## Best Practices

✅ **DO:**
- Run comparison before starting work
- Pull latest at the start of each day
- Commit changes frequently (at least daily)
- Push to GitHub after committing
- Use meaningful commit messages
- Review sync reports regularly

❌ **DON'T:**
- Skip comparison before work
- Let changes accumulate without pushing
- Force-push to main branches
- Modify registry manually without understanding impact
- Ignore sync failures
- Commit secrets or credentials

## Troubleshooting

### Workspaces stuck in BEHIND status
```powershell
.\scripts\Pull-LatestFromAllWorkspaces.ps1 -Force
```

### GitHub authentication fails
```powershell
gh auth login
```

### Workspace not in registry
Add to `config/workspaces-config.json` and re-run scripts.

### Merge conflicts during pull
```powershell
# Abort the pull
git merge --abort

# Inspect the conflict
git diff

# Resolve manually or use -Force
.\scripts\Pull-LatestFromAllWorkspaces.ps1 -Force
```

## Support & Maintenance
